## 2. 거래량 매수/매도 우위 색상 (검토)

### 2.1 사실 확인

- 우리 데이터(yfinance 일별 OHLCV)에는 **매수/매도 체결 구분(체결강도) 정보가
  없다.** 일별 봉 데이터로는 어떤 소스든 체결 방향을 알 수 없다.
- 일반 차트 소프트웨어(HTS·트레이딩뷰류)의 거래량 막대 색도 실제로는 **그날
  가격이 올랐는지/내렸는지(종가 vs 전일 종가 또는 시가)로 칠하는 근사**이지
  체결강도가 아니다.

### 2.2 옵션 비교

| 옵션 | 내용 | 평가 |
|---|---|---|
| (a) 가격 등락 기반 색 + 정확한 라벨 | 표시 중인 시리즈(DR 또는 원주)의 종가가 전일 종가 대비 상승이면 빨강, 하락이면 파랑, 보합·이월일은 중립(회색). 범례에 `색상: 전일 종가 대비 등락 기준` 명시 | 업계 관례와 일치, 구현 소(추정 - 기존 F6 바에 색 분기 + 범례 1줄). 라벨만 정확하면 투명성 원칙과 충돌 없음 |
| (b) 실제 체결강도 소스 도입 | 국내 증권사 OpenAPI(한국투자증권 등)의 체결강도 데이터 | **반대.** KRX 원주 한정(미국 DR·홍콩 미커버 - 반쪽 데이터), 계좌·개인 키 필요, 시세 재배포 제약(추정), 실시간 계열이라 정적 EOD 구조와 충돌. 비용 대비 효익 없음 |
| (c) 미도입 | 현행 단색 유지 | 사용자 요청 취지(시각 정보)를 버림 - 차선 |

### 2.3 권고

- **(a) 조건부 반영.** 조건:
  1. 화면 어디에도 "매수 우위/매도 우위/체결강도" 표현을 쓰지 않는다 (사실과
     다른 라벨 금지 - 투명성 원칙).
  2. 범례 문구 확정: `거래량 색: 해당 시장 종가의 전일 대비 상승(빨강)/하락
     (파랑)/보합·이월(회색)`.
  3. 비교 기준은 "같은 시리즈의 직전 거래일 종가"(이월일은 중립 처리 - 등락
     판정 불가).
- 완료 기준: [ ] 표본 5일 색상이 원천 종가 등락과 일치 [ ] 이월일 회색
  [ ] 범례 문구 노출 [ ] 금지 표현 미사용 [ ] 두 테마 대비 측정 목록에
  거래량 색 추가.
- 관리자가 사용자에게 전달할 요지: "매수/매도 우위 자체는 어떤 일별 데이터로도
  제공되지 않으며, 통상의 차트들도 가격 등락 색을 쓴다. 같은 방식으로 하되
  기준을 화면에 정확히 표기하겠다."

## 3. 1개월 무료 비상업 운영 + 무료 도메인 (검토·조사)

### 3.1 아이디어 평가 - 수요 검증 방법으로서

- 타당성 있음: 실트래픽·검색 유입·재방문 데이터(D6 분석 도구 병행 필요)를 얻는
  가장 빠른 방법이고, 기획 문서(`2026-08-03-bm-feasibility.md` 제안 B)의 "지출
  시작 전 준비" 노선과도 일치한다. 뉴스 사이클(SKHY 프리미엄)이 살아있는 지금이
  실험 적기라는 점도 동의.
- 단, 두 가지가 성패를 가른다: (1) 데이터 라이선스(3.2) (2) 1개월 후 이전
  비용을 낮추는 도메인 선택(3.3).

### 3.2 데이터 라이선스 리스크 (솔직 평가)

- **핵심: "비상업"이어도 문제가 사라지지 않는다.** 야후 약관은 데이터의 공개
  표시·재배포 자체를 사전 동의 없이 금지하며(상업 여부와 별개 조항), yfinance는
  비공식 라이브러리다 (약관: https://legal.yahoo.com/us/en/yahoo/terms/product-atos/apiforydn/index.html ,
  yfinance 고지: https://ranaroussi.github.io/yfinance/ ). 기존 사용자 승인
  범위는 "비공개 프로토타입 한정"이므로 **공개 운영은 어떤 형태든 승인 범위
  초과 - 사용자 재승인 필수.**
- 옵션 비교:

| 옵션 | 내용 | 리스크·비용 평가 |
|---|---|---|
| (i) yfinance 그대로 + 리스크 감수 | 현행 파이프라인 무변경, 광고 없음·출처 표기·1개월 한정 | 법적 조치 확률: 소규모 비상업 사이트 대상 사례는 확인하지 못했고 낮다고 판단(추정). 실질 리스크는 **야후 측 차단·레이트리밋으로 갱신이 멈추는 운영 리스크**와 약관 위반 상태의 지속(회사 원칙과 배치). 공수 0 |
| (ii) 무료 공식·무료 티어 조합으로 부분 전환 (권고) | 미국 DR: Alpha Vantage 무료 25콜/일(개인·비상업 - 일 1회 EOD 12~13콜이라 수량 충분, https://www.alphavantage.co/premium/ ) / KRX: KRX OpenAPI(상업 금지 조항 - **비상업 실험엔 부합 가능성, 약관 원문 확인 선행**, https://openapi.krx.co.kr/ ) / TWSE 공식 / 환율: ECOS·수출입은행 | 약관 정합성이 가장 높다. 공수: 수집부 다중 소스 모듈화(BM 문서 기존 과제와 동일 작업 - 상업 전환 시 어차피 필요한 투자). **미확인 2건: Alpha Vantage의 홍콩(9988.HK)·런던(SMSN) 커버리지** - 미커버 종목은 실험 기간 "지원 예정" 처리로 제외(종목 축소 비용) |
| (iii) 프리미엄 %(계산값)만 표시 + 원천값 숨김 | 재배포 색채 완화 시도 | 파생 데이터도 원천 약관 제약을 벗어난다고 단정 불가(기존 평가와 동일 - 추정)이며, **"계산 근거 투명성"이라는 우리 차별점을 스스로 버리는 구성** - 비권고 |

- **권고**: 원칙 부합 순서로 **(ii)를 1안**으로 한다 - 단 개발 공수(수집부
  모듈화 + 소스별 검증)를 개발팀이 견적한 뒤, 공수가 실험 시기를 놓칠 수준이면
  **(i)을 사용자 명시 승인(약관 위반 리스크 고지 포함) 조건으로 2안** 채택.
  어느 쪽이든 광고·수익화 장치 미부착(비상업 명확화), 데이터 출처·지연 표기,
  1개월 후 계속 여부 재결정 시점을 사전에 정한다.

### 3.3 무료 도메인 방법 조사 (웹 조사)

| 방법 | 상태·내용 | SEO·이전 비용 평가 |
|---|---|---|
| GitHub Pages `*.github.io` | 무료, HTTPS, 정적 호스팅 겸용(현 구조와 정합). | 서브도메인도 색인은 정상. **가장 큰 장점: 이후 커스텀 도메인을 설정하면 기존 github.io URL이 자동 301 리다이렉트**되어 SEO 이전 비용이 낮다 ( https://finisky.github.io/en/migrate-github-pages-by-301-redirects/ , https://github.com/orgs/community/discussions/22407 ). 이전 시 서치콘솔 수동 통지 필요, 순위 재안착에 수개월(일반론) |
| Cloudflare Pages `*.pages.dev` / Netlify `*.netlify.app` | 무료, 커스텀 도메인 추가·리다이렉트 기능 보유(추정 - 플랜 조건 확인 필요) | github.io와 유사. 현 파이프라인이 GitHub Actions 전제라 GitHub Pages가 통합 단순 |
| 무료 TLD (Freenom .tk/.ml 등) | **사용 불가** - Freenom은 Meta 소송 후 2024-02 도메인 사업 철수, 등록 중단·기존 도메인 대량 소멸 ( https://krebsonsecurity.com/2023/03/sued-by-meta-freenom-halts-domain-registrations/ , https://www.netcraft.com/blog/cloudflare-loses-22-of-its-domains-in-freenom-tk-shutdown ) | 논외. 유사 무료 TLD는 피싱 연관 평판 때문에 금융 정보 사이트 신뢰도에 역효과 |
| eu.org 등 무료 서브도메인 등록 서비스 | 운영 중( https://nic.eu.org/ ) - 승인 지연(수일~수주) 알려짐 | 금융 사이트 신뢰도·브랜드 관점 비권고. 이전 시 리다이렉트를 자체 관리해야 함 |
| (비교용) 유료 도메인 | .com 등 연 1~2만원 수준 | **이전 비용 0** (처음부터 최종 도메인). 서치콘솔·백링크·북마크 자산이 그대로 누적. 1개월 실험이 성공하면 어차피 구매하게 됨 |

### 3.4 권고안 - 1개월 실험 최적 구성

1. **도메인**: 비용을 완전히 0으로 하려면 `*.github.io`(자동 301 이전 경로
   확보됨)가 최선. 다만 **연 1~2만원의 유료 도메인을 처음부터 쓰는 것이 이전
   비용(리다이렉트 관리·순위 재안착 수개월·서치콘솔 이관)을 원천 제거하므로
   기획팀은 소액 지출을 권고**한다 - "무료" 요청과 다른 부분이라 사용자 결정
   사항으로 명시. (절충: github.io로 시작하되 실험 2주차에 지속 신호가 보이면
   즉시 커스텀 도메인 연결 - 자동 301로 손실 최소화)
2. **호스팅**: GitHub Pages (정적 구조·Actions 자동 갱신과 정합, 무료).
3. **데이터**: 3.2 권고 순서 (1안 = 부분 전환(ii), 공수 초과 시 2안 = 사용자
   명시 승인 하 yfinance(i)).
4. **비상업 명확화**: 광고·제휴·후원 일절 미부착, 푸터에 비상업 실험 운영 고지
   + 데이터 출처·지연 표기 + 투자 조언 아님 고지(기존).
5. **측정 준비**: 방문 분석 도구(D6 - 미구현)와 서치콘솔 등록을 실험 시작 전에
   갖춘다 - 수요 검증 실험에서 측정이 없으면 의미가 없다.
6. **종료 조건 사전 합의**: 1개월 후 (a) 상업 전환(유료 API 계약 + 수익화) (b)
   비공개 회귀 (c) 연장 - 판단 기준(예: 주간 UV, 재방문율, 검색 유입 추이)을
   시작 전에 사용자와 합의.

## 4. 결정 필요 사항 (관리자 -> 사용자)

1. (요청 3) 공개 운영의 데이터 옵션 선택: 1안 (ii) 부분 전환(개발 공수 발생,
