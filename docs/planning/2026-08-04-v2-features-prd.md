## 0. 배경과 범위

- 사용자(사장)가 기능 검토 문서의 8개 항목 전부 진행을 확정했다. 재문의 약속
  항목이던 거래량(F6)·전환한도 계열(F7)도 **포함 확정**(수동 관리 + 기준일 표기
  방식 전제 승인), 시가총액(F8)이 추가 확정됐다.
- 본 PRD는 1차 PRD(`2026-08-03-adr-premium-prd.md`)와 현 구현(설계 문서
  `2026-08-03-adr-premium-design.md`: 정적 EOD + 프리렌더 14페이지 + 자체 SVG
  차트 + 하이드레이션 app.js)을 전제로 한 **증분 명세**다. 기존 명세와 충돌하는
  부분만 본 문서가 우선한다.
- 데이터 소스는 계속 yfinance(비공개 프로토타입 한정, 사용자 승인 범위). 공개
  수익화 전 상업 API 전환 방침 불변.

### 공통 원칙 (검토 문서 6.4절 유지)

1. 추가 지표(SMA·평균선·거래량)는 **기본 꺼짐(토글)** - 기본 화면은 "프리미엄
   라인 + 0% 기준선"의 단순함을 유지한다.
2. 새 지표·수치마다 계산식을 상세 화면 수식 안내 섹션에 추가한다(투명성 차별점).
3. "투자 조언 아님" 고지 유지. 통계·수급 수치 근처에 기준일·출처 라벨 필수.
4. 문서·화면 표기는 ASCII 기호만 사용(곱셈 *, 마이너스 -, 화살표 ->).
5. 색상은 기존 WCAG 검증 변수 재사용. 상승 빨강/하락 파랑 + 부호(+/-) 항상 병기.

## 1. F1: 차트 드래그 패닝

- **화면 위치**: 종목 상세 메인 차트.
- **동작 명세**:
  - 기간 탭(1M/3M/6M/1Y)이 "윈도우 길이"를 정하고, 드래그는 윈도우의 끝
    날짜를 좌우로 이동한다. MAX에서는 패닝 비활성(전체가 이미 보임).
  - 마우스: pointerdown 후 좌우 드래그 = 이동. 드래그 중 툴팁 억제, 놓으면 복원.
  - 터치: `touch-action: pan-y` 유지. 수평 이동량 > 수직 이동량일 때만 패닝
    개시(임계값 예: 10px) - 세로 페이지 스크롤을 막지 않는다.
  - 키보드: 차트 영역 포커스(tabindex) 상태에서 좌/우 화살표 = 윈도우 길이의
    10%씩 이동.
  - 과거 끝(데이터 시작)·최신 끝에서 멈춤(오버스크롤 없음). 패닝 상태에서 기간
    탭을 다시 누르면 최신 구간으로 복귀. 패닝 중임을 알리는 표시(예: 탭 옆
    "과거 구간" 라벨 + "최신으로" 버튼)를 제공한다.
- **계산식**: 없음 (표시 윈도우 이동만).
- **데이터 요건**: 없음 (전체 히스토리 JSON 기로드).
- **완료 기준**:
  - [ ] 1Y 선택 후 좌측 드래그로 1년 이전 구간이 표시되고, 우측 드래그·"최신으로"
        버튼으로 복귀한다 (TSM 등 장기 종목 실측).
  - [ ] 모바일(375px)에서 차트 위 세로 스와이프 시 페이지가 스크롤되고, 가로
        스와이프 시에만 패닝된다.
  - [ ] 키보드 화살표로 윈도우가 이동한다.
  - [ ] 데이터 시작 이전으로 이동하지 않는다. 패닝 중 콘솔 에러 0건.
  - [ ] 외부 차트 라이브러리 미도입(의존성 0 유지).

## 2. F2: 오늘자 프리미엄에 장중(지연) 시세 사용

사용자 확정: 지연 시세 허용, 단 **"당일 현재가는 지연 시세"임을 명시**.

- **화면 위치**: 메인 카드의 현재 프리미엄 %, 종목 상세 상단 스냅샷 카드(현재
  프리미엄 + 원천값 4종). **차트(일별 확정 종가 시계열)에는 반영하지 않는다.**
- **방식 (검토 문서 방식 A 확정)**: 장중 시간대에 파이프라인(fetch -> build)을
  주기 재실행해 스냅샷만 최신화한다. 규칙 A(PRD 3.3.1)의 이행 수준 상향이며
  규칙 자체는 불변.
- **장중 갱신 스케줄 (제안 - 개발팀이 실행 시간 실측 후 간격 조정 가능)**:

  | 세션 | 대상 시장 | 시간(KST 기준) | 갱신 간격 |
  |---|---|---|---|
  | 아시아 | KRX(09:00-15:30), TWSE(10:00-14:30) | 09:00~15:30 | 60분 (UTC 0~6시 매시) |
  | 아시아 마감 확정 | KRX·TWSE 종가 확정 반영 | 15:40 경 1회 (UTC 06:40) | 1회 |
  | 런던(선택) | LSE IOB - SMSN 1종목(16:00/17:00~00:30/01:30) | 17:00~22:00 | 120분 (개발팀 재량 - 효익 대비 실행 비용 판단) |
  | 미국+런던 후반 | 미국 정규장(22:30/23:30~05:00/06:00) | 23:00~06:00 | 60분 (UTC 14~21시 매시) |
  | 일일 확정 (기존) | 전 시장 확정 종가 + 차트 히스토리 갱신 | 06:30 (UTC 21:30) | 1회 (기존 워크플로) |

  - GitHub Actions cron은 정시 보장이 없어(10~30분 지연 흔함) 라벨은 반드시
    "수집 시각" 기준으로 표기한다.
- **지연 라벨 표준 (필수)**:
  - 데이터 사실(웹 조사, Yahoo 공식 거래소 페이지 https://help.yahoo.com/kb/SLN2310.html ):
    나스닥 실시간, KRX/TWSE/LSE 20분 지연, 환율 실시간. 단 수집 주기가 있으므로
    화면에는 전 시장 공통으로 "지연 시세"로 표기한다(사용자 지시 부합, 과대 표기
    방지).
  - 스냅샷 영역 공통 배지: `장중 지연 시세 기준 - 수집 <MM/DD HH:MM KST>`
  - 값별 라벨 형식(원천값 4종 카드):
    - 장중 수집 값: `<값> - 장중 지연 시세 (수집 HH:MM)`
    - 확정 종가: `<값> - <MM/DD> 종가`
    - 이월: `<값> - <MM/DD> 종가 (휴장 이월)` (기존 유지)
  - 스냅샷 하단 각주 1줄: `장중 값은 거래소 지연(최대 20분)과 갱신 주기(최대
    60분)로 실제 현재가와 다를 수 있습니다.`
- **차트 분리 원칙**: history/<ID>.json에는 확정 종가 포인트만 기록한다. 장중
  값은 meta.json 스냅샷 필드에만 존재하며, 당일 포인트는 일일 확정 실행(06:30)
  에서만 차트에 추가된다. (미확정 값이 차트에 섞여 다음날 바뀌는 혼란 방지)
- **데이터 요건**: 현행 수집 코드로 가능(yfinance는 개장 중 당일 값을 진행 중
  가격으로 반환 - 설계 문서 7절-3 실측 확인). 스냅샷 전용 경량 수집(당일 시세만
  조회)로 실행 시간 단축 권장(개발팀 판단).
- **완료 기준**:
  - [ ] 한국 장중(예: KST 11시) 수집 시 원주 값이 당일 장중가로, DR 값이 직전
        미국 종가로 표시되고 각각 라벨 형식이 위 표준과 일치한다.
  - [ ] 미국 장중 수집 시 DR 값이 장중가 + "장중 지연 시세 (수집 HH:MM)" 라벨로
        표시된다.
  - [ ] 공통 배지·각주 문구가 메인·상세 모두 노출된다.
  - [ ] 장중 실행 후에도 history JSON의 당일 포인트가 추가·변경되지 않고, 일일
        확정 실행에서만 추가된다.
  - [ ] 장중 실행 실패 시 기존 실패 처리(마지막 정상값 + "갱신 실패, OO 기준")가
        동일 동작한다.

## 3. F3: 일/주/월 단위 프리미엄 표시

- **화면 위치**: 종목 상세 차트 - 기간 탭 옆 단위 토글 `[일|주|월]`.
- **집계 규칙 (사용자 확정)**: 해당 주/월의 **마지막 거래일 값**을 그 주/월의
  값으로 한다. 주 경계는 ISO 주(월~일), 월 경계는 캘린더 월. 마지막 포인트가
  이월가면 이월 플래그를 승계해 툴팁에 표기한다. 화면에 집계 기준을 명시한다
  (차트 하단: `주/월 단위는 해당 기간 마지막 거래일 기준입니다.`).
- **조합 규칙**: 1M/3M = 일 고정(토글 비활성), 6M/1Y = 일/주, MAX = 일/주/월.
  단위 변경 시 선택 기간 유지.
- **계산 위치**: 클라이언트(app.js) 다운샘플 - 데이터 파일·파이프라인 변경 없음.
- **툴팁**: `2026-07-31 (주: 07-27~07-31) +16.02%` 형식으로 집계 구간 표기.
- **완료 기준**:
  - [ ] TSM MAX + 월 단위에서 포인트 수가 월 수와 일치하고, 각 값이 해당 월
        마지막 거래일의 일별 값과 일치한다 (표본 3개월 수기 대조).
  - [ ] 주 단위 표본 3주 수기 대조 일치. 마지막 거래일이 이월가인 주의 툴팁에
        이월 표기가 승계된다.
  - [ ] 1M/3M에서 토글이 비활성이고, 6M/1Y에서 월이 선택 불가하다.
  - [ ] 집계 기준 안내 문구가 주/월 선택 시 노출된다.

## 4. F4: 전일 대비 변동 표시 (%p)

- **화면 위치**: 메인 카드 + 종목 상세 스냅샷 카드의 현재 프리미엄 % 옆.
- **표시 형식**: `+16.02% (+1.25%p, 8/1 대비)` - 단위는 반드시 **%p**, 부호
  항상 병기, 색상은 기존 변수(상승 빨강/하락 파랑). 메인 카드는 공간상
  `(+1.25%p)`로 축약하고 비교 기준일은 툴팁(title 속성)으로 제공 가능.
- **계산식**: `delta_pp = premium_today - premium_prev` (규칙 B 시계열의 직전
  데이터 포인트 대비. 양쪽 휴장일은 포인트가 없으므로 자동으로 직전 거래일).
  F2 장중 값이 표시 중일 때는 "장중 스냅샷 vs 직전 확정 포인트" 차이임을 라벨로
  구분하지 않고 동일 형식 유지하되, 스냅샷 배지(F2)가 시점을 설명한다.
- **데이터 요건**: meta.json 스냅샷에 직전 포인트의 프리미엄·날짜 필드 추가
  (파이프라인 수 줄). 프리렌더 템플릿에도 동일 값 삽입(크롤러 노출).
- **완료 기준**:
  - [ ] 표본 3종목에서 (오늘 값 - 직전 포인트 값)과 표시 %p가 +/-0.01%p 이내
        일치, 비교 기준일이 직전 포인트 날짜와 일치한다.
  - [ ] 부호·색상·"%p" 단위가 표시되고, 프리렌더 원시 HTML에도 존재한다.
  - [ ] 직전 포인트가 없는 경우(상장 첫 데이터) 괄호 영역이 생략된다.

## 5. F5: 이동평균선 (SMA 20/60일) + 기간 평균선

- **화면 위치**: 종목 상세 차트 오버레이. 토글 3개(`SMA20`, `SMA60`,
  `기간 평균`) - **기본 꺼짐**.
- **계산식** (클라이언트 계산, 수식 안내 섹션에 게재):
  - `SMA_n(d) = 직전 n개 데이터 포인트(거래일 기준, d 포함)의 프리미엄 단순 평균`
  - 데이터가 n개 미만인 구간은 그리지 않는다 (SKHY처럼 짧은 종목은 SMA60이
    아예 없을 수 있음 - 토글은 표시하되 "데이터 부족" 상태 표기).
  - SMA는 **일 단위 시계열 기준**으로 정의한다. 주/월 단위 뷰에서는 SMA 토글
    비활성(의미 혼선 방지), 기간 평균선만 허용.
  - `기간 평균 = 현재 화면에 표시 중인 구간(기간 탭 + 패닝 윈도우)의 프리미엄
    단순 평균` - 수평 점선 + 우측 끝 값 라벨. 윈도우 이동·기간 변경 시 재계산.
- **스타일**: 프리미엄 본선과 구분되는 색(테마별 WCAG 3:1 이상, 신규 색 변수는
  테스트팀 대비 측정 목록에 추가), 범례 표시.
- **완료 기준**:
  - [ ] SMA20 표본 1일 수기 계산(20개 값 평균)과 차트 값이 +/-0.01%p 이내 일치.
  - [ ] 기간 평균선이 1Y 구간 평균과 일치(수기 대조)하고, 패닝 시 재계산된다.
  - [ ] 토글 기본 꺼짐, 켠 상태는 세션 내 유지(종목 이동 시 초기화 허용).
  - [ ] 주/월 단위에서 SMA 토글이 비활성이다.
  - [ ] 수식 안내 섹션에 SMA·기간 평균 정의가 추가돼 있다.

## 6. F6: 거래량 표시

- **화면 위치**: 종목 상세 차트 **하단 서브패널(바 차트)**. 토글 `거래량`
  기본 꺼짐. 켜면 시리즈 선택 `[DR|원주]`(기본 DR).
- **표시 형식**: 일별 거래량 바(단위: 주. DR = ADS 주 수, 원주 = 원주 주 수).
  축 라벨에 단위 명시(`백만 주` 축약). 주/월 단위 뷰에서는 해당 기간 **합계**
  거래량(집계 규칙: 기간 내 실거래일 합) - 마지막 값이 아닌 합계임을 툴팁에 표기.

## 7. F7: 전환한도 + 현재 전환율 + 시장별 주식 금액 (최중요)

### 7.1 화면 위치·구성

종목 상세에 **"전환 현황" 섹션**(원천값 카드 아래) 신설. 구성 요소:

1. ADR 전환한도 (한도 확인 종목만): `전환한도: 원주 기준 17,790,000주 (기준일
   2026-07-29, 회사 컨콜)`
2. 현재 전환율(= DR 형태 주식 비중)과 한도 소진율(한도 확인 종목만): 수평
   게이지 바 + 수치.
3. 시장별 주식 금액: DR 시장 / 현지 시장 두 칸 병렬 표시.
4. 데이터 출처·기준일 라벨(필수) + 설명 각주.

메인 카드에는 넣지 않는다(밀도 유지).

### 7.2 정의·계산식 (수식 안내 섹션에 그대로 게재)

기호: `N_dr` = DR 발행 잔량(ADS 주 수), `r` = 전환비율(DR 1주당 원주 수),
`N_total` = 원주 총발행주식수, `P_dr` = DR 가격(USD), `P_local` = 원주
가격(현지통화), `FX` = USD당 현지통화, `L` = 전환한도(원주 기준 주 수).

```
DR 물량의 원주 환산:  N_dr_local = N_dr * r

현재 전환율(%):       cv = N_dr_local / N_total * 100
  (전체 발행주식 중 DR 형태로 예탁된 비중)

한도 소진율(%):       lu = N_dr_local / L * 100   (L이 확인된 종목만)

DR 시장 금액:         V_dr = N_dr * P_dr                  (USD)
현지 시장 금액:       V_local = (N_total - N_dr_local) * P_local  (현지통화)
```

- **통화 표시 방침**: 각 금액을 해당 시장 통화로 우선 표기하고 괄호에 상대
  통화 환산 병기. 예: `DR 시장: $26.7억 (약 3.7조원)` / `현지 시장: 291.2조원
  (약 $2,103억)`. 환산에는 스냅샷 FX 사용, 축약 단위(조원/억 달러) 표준은
  기존 시총 표기와 통일.
- **정직성 각주(필수)**: `두 시장 금액의 합은 시가총액과 일치하지 않을 수
  있습니다. DR 시장 금액은 프리미엄이 반영된 DR 가격 기준이기 때문입니다.`
  (V_dr + V_local != F8 시총. 투명성 원칙상 명시)
- 게이지 바: 0~100% 축에 cv 표시. 한도 확인 종목은 한도 위치(L/N_total * 100)를
  눈금으로 함께 표시해 "한도까지 여유"가 보이게 한다.

### 7.3 데이터 수급 (조사 결과와 확정 방침)

**(1) N_dr (DR 발행 잔량) - 자동 조회 후보와 검증 절차**

- 조사 결과: Yahoo/yfinance의 발행주식수 필드가 DR 티커에서 "실제 ADS 잔량"인지
  "전사 발행주식의 ADS 환산치"인지는 **종목마다 다를 수 있고 일반화된 문서가
  없다**(yfinance 이슈·해설에서도 정의가 불명확:
  https://github.com/ranaroussi/yfinance/issues/1133 ,
  https://zoo.cs.yale.edu/classes/cs458/lectures/yfinance.html ). Yahoo의 ADR
  페이지 시총은 통상 전사 기준으로 표시되는 점에서 전사 환산치일 가능성이
  높은 종목이 많다(추정). 예탁은행의 잔량 데이터(Citi Issuer Access)는 발행사
  전용 비공개 플랫폼으로 공개 일별 피드가 없다
  ( https://services.citi.com/solutions/issuer-services ).
- 따라서 **자동값은 반드시 검증을 통과했을 때만 사용**한다:
  - 조회 필드 후보(우선순위): `info.sharesOutstanding` ->
    `info.impliedSharesOutstanding` -> `fast_info`의 주식수 필드. 개발팀이 11개
    DR 심볼 전부 실조회해 반환값을 본 PRD 9절 확인표에 기록한다.
  - 검증 A (전사 환산치 배제): `N_dr_candidate * r`가 `N_total`의 90% 이상이면
    "전사 발행량의 ADS 환산치"로 간주하고 **기각**한다. (실제 DR 잔량이 전체의
    90%를 넘는 종목은 우리 대상에 없다고 판단 - 추정. 임계값은 설정 파일로 조정
    가능하게)
  - 검증 B (한도 정합): 한도 확인 종목은 `N_dr_candidate * r <= L * 1.05`여야
    한다. 위반 시 기각.
  - 검증 통과 시 라벨: `자동 조회(Yahoo) 기준, <조회일>`.
- **(2) 수동 폴백 (사용자 승인 방식)**: 설정 파일(tickers.json)에 종목별
  `dr_outstanding_manual` + `dr_outstanding_as_of`(기준일) + `dr_outstanding_src`
  (출처 URL/설명)를 둔다. 자동값이 기각·조회 불가면 수동값을 사용하고 라벨:
  `수동 입력 기준일 <as_of> (출처: <src>)`. 수동값 갱신은 운영 절차(분기 1회
  전환비율 점검과 동일 주기)로 관리.
- **(3) 최종 폴백**: 자동·수동 모두 없으면 전환율·시장별 금액을 계산하지 않고
  `데이터 미확인` 표시(섹션은 유지하되 값 자리에 대시(-)와 안내 문구). 오류처럼
  보이지 않게 회색 처리.

**(2) N_total (원주 총발행주식수)**

- 원주 티커(.KS/.TW/005930.KS 등)의 발행주식수 필드로 조회. 원주 시총은 이미
  fast_info로 실측 사용 중(설계 문서 4절)이므로 `market_cap / P_local` 역산도
  교차 검증 수단이 된다. 두 값이 5% 이상 어긋나면 파이프라인 경고 로그.
- 갱신: 일 1회(일일 확정 실행 시). 스냅샷에 조회일 기록.

**(3) L (전환한도) - 설정 파일 수동 관리 (사용자 승인 방식)**

- 공식 일별 피드가 없으므로 tickers.json에 `conversion_limit_local`(원주 기준
  주 수) + `limit_as_of` + `limit_src`를 수동 기재한다.
- 확인된 종목: **SKHY = 17,790,000주** (2026-07-29 실적 컨콜 발언 기준,
  출처: https://www.newspim.com/news/view/20260729000369 ,
  http://www.inews24.com/view/1989786 ). ADR -> 원주 전환은 2026-07-30부터 자유,
  원주 -> ADR 방향은 한도·신고 절차 제약 - 이 비대칭 설명을 섹션 각주 1줄로
  제공한다.
- 미확인 종목: 한도 필드 없음 -> 화면에 한도·소진율 행을 **표시하지 않는다**
  (빈 값 노출 금지). 전환율(cv)·시장별 금액은 N_dr가 있으면 표시.
- 기획팀 후속 조사로 타 종목 한도(예탁계약·20-F)를 확인하면 설정 파일에 추가
  하는 방식으로 확장(코드 변경 불필요).
