## 1. 검토 전제 (현 구현 상태)

설계 문서(`docs/development/2026-08-03-adr-premium-design.md`) 기준:

- 정적 EOD 사이트: 파이프라인(fetch_data.py)이 일별 프리미엄 JSON 생성 ->
  프리렌더(build_pages.py)가 14페이지(메인 1 + 종목 11 + 가이드 2) HTML 생성.
  서버 사이드 없음.
- 차트는 자체 SVG(약 150줄) + app.js 하이드레이션(기간 탭 1M/3M/6M/1Y/MAX, 툴팁).
  상세 화면은 종목별 전체 히스토리 JSON(history/<ID>.json)을 이미 클라이언트에
  로드한다 (최대 약 5,880 포인트 - TSM).
- 갱신은 일 1회(KST 06:30, 미국 정규장 마감 직후) 전제. 프리렌더 숫자는 빌드
  시점 스냅샷(제약 10).
- 아래 구현 난이도·규모는 기획팀의 개발 관점 **추정**이며, 착수 전 개발팀
  확인이 필요하다.

## 2. 요청 1: 차트 드래그 패닝

**내용**: 1Y 등 기간 선택 후 차트를 마우스로 좌우 드래그하면 시간축 윈도우 이동.

- 구현 방식 (추정): app.js 차트 하이드레이션에 표시 윈도우 상태(시작 인덱스 +
  기간 길이)를 도입하고, pointerdown/pointermove/pointerup 이벤트로 윈도우를
  이동하며 SVG를 재렌더. 데이터는 이미 전체 히스토리가 로드돼 있으므로 **데이터
  요건 추가 없음**. 기간 탭과의 관계: 패닝 시작 시 탭은 "기간 길이" 의미로
  유지하고 끝 날짜만 이동(탭 재클릭 시 최신으로 복귀) 방식이 단순하다.
- 난이도: 중 (추정). 일별 포인트 수천 개 수준의 SVG 재렌더는 성능 문제 없음.
  까다로운 부분 2가지 - (1) **모바일: 가로 드래그(패닝)와 세로 스크롤의 구분**
  (touch-action: pan-y + 수평 제스처 판별). 미처리 시 모바일에서 페이지 스크롤이
  막히는 역효과 (2) 패닝 상태와 툴팁(호버 크로스헤어)의 이벤트 충돌 정리.
- 사용자 가치: TSMC(약 20년)·삼성전자(2018~) 같은 긴 히스토리의 과거 구간 탐색이
  현재는 MAX 축소로만 가능한데, 패닝으로 "특정 시기 확대 관찰"이 가능해진다.
  체류 시간·재방문에 긍정적. SEO 직접 효과는 없음.
- 단점·리스크: 자체 SVG 코드 복잡도 증가(현재 약 150줄 -> 추정 +100~150줄).
  차트 라이브러리 도입 유혹이 생기지만 의존성 0 원칙 유지가 가능한 규모다.
  키보드 사용자 대안(좌/우 화살표 이동)을 넣으면 접근성도 유지된다.
- **권고: 반영.** 조건 - 모바일 터치 구분 처리와 키보드 대안 포함, 라이브러리
  도입 없이 자체 구현 유지.

## 3. 요청 2: 오늘자 프리미엄에 현재가(장중 시세) 사용

**내용**: 종가 기준 계산은 유지하되 오늘 값은 가능하면 현재가로.

### 3.1 데이터 사실 확인 (웹 조사)

- Yahoo Finance 공식 지연 정책(거래소·데이터 제공자 페이지,
  https://help.yahoo.com/kb/SLN2310.html 조회): **나스닥 실시간, 한국거래소
  20분 지연, 대만거래소 20분 지연, 런던거래소 20분 지연, 환율 실시간.**
  즉 yfinance 경유로도 "현재가"는 정확히는 시장별 0~20분 지연 시세다.
- yfinance는 개장 중 시장의 당일 값을 진행 중 가격으로 반환한다는 점은 개발팀이
  이미 실측 확인(설계 문서 7절-3). 별도 엔드포인트 없이 현행 수집 코드로 장중
  스냅샷 취득이 가능하다.
- PRD 3.3.1 **규칙 A가 이미 이 동작을 정의**하고 있다: 각 시장의 가장 최근
  체결가 사용 + 각 값의 기준 시점 라벨 표기("실시간(20분 지연)" 등). 즉 이 요청은
  PRD 신규 항목이 아니라 규칙 A의 이행 수준을 올리는 것이다.

### 3.2 "현재가"를 정적 사이트에서 확보하는 방식 비교

| 방식 | 내용 | 판단 |
|---|---|---|
| A. 주기적 재생성 (권고) | 장중 시간대(예: 미국 정규장 + 한국 정규장)에 GitHub Actions 스케줄로 파이프라인을 30~60분 간격 재실행(fetch -> build). 스냅샷 전용 경량 fetch(당일 시세만)로 실행 시간 단축 가능(추정) | 정적 구조 완전 유지. 체감 지연 = 재생성 주기 + 소스 지연 + Actions 스케줄 지연(10~30분 흔함) = 약 40~90분. "현재가"라기보다 "장중 준실시간" - 라벨만 정확하면 가치 충분 |
| B. 클라이언트가 Yahoo를 직접 호출 | 브라우저 JS가 Yahoo 비공식 API를 호출해 현재가 표시 | **반대.** (1) Yahoo 엔드포인트는 브라우저 교차 출처(CORS) 호출이 차단되는 것으로 알려져 프록시 서버가 필요(추정) - 정적 구조 이탈 (2) 방문자 브라우저가 직접 약관 위반 트래픽을 만들어 위반 노출이 최대화 (3) 공개 전환 시 전면 재작업 |
| C. 서버리스 프록시(엣지 워커 등) | 워커가 시세를 중계·캐시 | 서버 요소 도입 + 약관 문제는 B와 동일. 상업 API 전환 후 "지연 시세 엔드포인트 중계"가 필요해지면 그때 재검토 |

### 3.3 정합성·라이선스

- "계산 근거 투명성" 차별점과의 정합: 장중 값은 혼합 시점(예: DR 20분 지연 시세
  + 원주 전일 종가 + 실시간 환율)이므로 **값별 기준 시점 라벨이 더 중요해진다.**
  규칙 A 라벨 요건을 그대로 이행하면 오히려 차별점이 강화된다. 라벨 없이 "현재가"
  로만 표시하면 차별점 훼손.
- 일별 히스토리(규칙 B)와의 분리: 장중 스냅샷은 "현재" 카드에만 반영하고, 차트의
  일별 확정 종가 시계열은 그대로 둔다(당일 포인트는 장 마감 후 확정). 미확정
  당일 값이 차트에 섞이면 다음날 수치가 바뀌는 혼란이 생긴다.
- 라이선스: yfinance 호출 빈도 증가는 비공개 프로토타입 한정 승인 범위 안에서는
  허용 가능하나, **공개 전환 시 상업 API의 장중/실시간 시세는 EOD보다 요금이
  높고 거래소 수수료가 따로 붙는 경우가 일반적(추정)** - 공개 단계의 장중 갱신
  주기는 API 견적(기획 문서 `2026-08-03-bm-feasibility.md` 3.3절)과 함께 결정해야
  한다.
- **권고: 고려 (조건부).** 방식 A로 "장중 30~60분 간격 갱신 + 값별 기준 시점
  라벨"까지만 반영하고, 그 이상(분 단위 실시간)은 반대. 조건 - (1) 차트의 확정
  종가 시계열과 분리 (2) 공개 전환 시 갱신 주기·비용을 사용자 승인으로 재확정.

## 4. 요청 3: 일/주/월 단위 프리미엄 표시

**내용**: 기간(1M/3M/6M...)에 더해 데이터 단위를 일/주/월로 전환.

- 구현 방식 (추정): 일별 시계열에서 주/월 단위 다운샘플. 프리미엄은 가격이
  아니라 비율이므로 OHLC 봉은 부자연스럽고, **"해당 주/월의 마지막 거래일 값"
  라인**(캘린더 주·월 경계 그룹핑)이 의미상 정확하다. 계산 위치는 클라이언트
  (app.js) 권장 - 전체 히스토리가 이미 로드돼 있어 데이터 파일 추가·파이프라인
  변경이 없고, 그룹핑 로직은 수십 줄 수준(추정). 난이도: 하~중.
- UI: 기간 탭 옆에 단위 토글(일/주/월). 조합 규칙 단순화 권장 - 1M/3M은 일 단위
  고정(주·월 단위는 포인트가 너무 적음), 6M/1Y는 일/주, MAX는 일/주/월 허용.
  툴팁에 "주 단위: 해당 주 마지막 거래일 기준" 명시(투명성 유지).
- 집계 시 이월 플래그 처리 정의 필요: 주 마지막 포인트가 이월가면 툴팁에 이월
  표기를 승계한다 (규칙 B 일관성).
- 사용자 가치: TSMC 20년 같은 장기 추세는 월 단위가 훨씬 읽기 쉽고, MAX 구간
  렌더 포인트 수가 수천 -> 수백으로 줄어 성능·가독 모두 개선. 요청 1(패닝),
  5(이동평균)와 시너지.
- 단점·리스크: 상태 조합(기간 x 단위 x 패닝)이 늘어 하이드레이션 코드 복잡도
  증가. "월 단위 값 = 월말 스냅샷"이라는 의미를 라벨로 명확히 하지 않으면 평균과
  혼동될 수 있다.
- **권고: 반영.** 조건 - 집계 규칙(마지막 거래일 값·경계 정의·이월 승계)을 위
  내용으로 확정하고 화면에 명시.

## 5. 요청 4: 전일 대비 변동 표시

**내용**: 현재 프리미엄 % 옆에 전일 대비 상승/하락 %p를 괄호로 표시.

- 구현 방식 (추정): 파이프라인 스냅샷 생성부에서 직전 유효 데이터 포인트의
  프리미엄을 함께 기록(meta.json 필드 추가) -> 프리렌더 템플릿·카드/상세
  하이드레이션에 표기. 수 줄~수십 줄 수준. 난이도: **하** (5건 중 최저).
- 정의를 명확히: "전일"은 규칙 B 시계열의 **직전 데이터 포인트**(양쪽 휴장일은
  포인트가 없으므로 자동으로 직전 거래일). 비교 대상 날짜를 툴팁 또는 병기로
  노출("+1.2%p (8/1 대비)") - 이월가가 낀 날의 착시를 라벨로 방지.
- 단위 정확성: 프리미엄은 비율이므로 전일 대비 변동은 **%가 아니라 %p**로
  표기해야 한다. 계산 투명성 차별점과 직결되는 표기 원칙.
- 색상: 기존 관례(상승 빨강/하락 파랑) 및 WCAG 검증된 색 변수 재사용. 색맹
  대비를 위해 부호(+/-)를 항상 병기.
- 사용자 가치: "어제보다 벌어졌나 좁혀졌나"는 핵심 시나리오(PRD 2절) 그 자체다.
  메인 카드의 정보 밀도를 크게 올리고 구현 비용은 최소.
- 단점·리스크: 사실상 없음. 카드 레이아웃 여백 조정 정도.
- **권고: 반영 (1순위 - 즉시).**

## 6. 요청 5: 투자자 참고 지표 조사와 차트 추가 후보

### 6.1 웹 조사 결과

**(1) ADR/DR 프리미엄 트레이딩 연구·실무**

- 아시아 ADR 페어 트레이딩 학술 연구: ADR-원주 가격 차이에 **비선형 평균회귀**가
  존재하며, 페어 트레이딩 수익의 주 원천은 ADR 쪽 포지션이고 중위 보유 기간이
  3일로 짧다 ( https://bauer.uh.edu/rsusmel/academic/adrarb_1.pdf ). 즉 실전
  사용자는 "프리미엄이 평소 범위에서 얼마나 벗어났는가"를 본다.
- 퀀트 실무 표준: 스프레드(괴리)의 **z-score**(롤링 평균 대비 표준편차 배수)로
  과열/과매도를 판단하고 임계값(예: +/-2)에서 진입·회귀 시 청산하는 구성이
  통용된다 ( https://statoasis.com/post/understanding-z-score-and-its-application-in-mean-reversion-strategies ,
  https://blog.quantinsti.com/epat-project-mean-reversion-statistical-arbitrage-pair-trading-strategy-indian-market-sectors/ ,
  https://www.tradingview.com/script/iPUJgiLI-Classic-Nacked-Z-Score-Arbitrage/ ).

### 6.3 2차 범위 항목 처리 (확정하지 않음)

거래량·전환 가능 물량(한도)은 PRD 6절(구 미해결 질문)에서 **2차 이후로 확정되며
"2차 범위 논의 시 사용자에게 재문의 필수"로 약속된 항목**이다. 본 문서는 확정하지
않고 재문의용 평가만 제공한다:

- 거래량: 포함 가치 중상(수렴 국면 판단 보조), 데이터 수급 용이(추정), 구현 부담
  하~중. 재문의 시 "포함" 의견.
- 전환 한도/잔여 여력: 포함 가치 상(SKHY 사용자의 실질 관심사), 그러나 자동
  데이터 수급 불확실 - "수동 갱신 + 기준일 표기" 방식의 운영 부담을 안내하고
  사용자 판단을 받을 것. 재문의 시 "조건부 포함(수동 갱신 방식 동의 시)" 의견.

### 6.4 지표 공통 원칙 (기획 의견)

- 모든 지표는 **기본 꺼짐(토글)** - 기본 화면은 "프리미엄 + 0% 기준선"의 단순함
  유지. 지표 추가로 첫인상 복잡도가 올라가면 일반 사용자(주 타깃) 이탈 위험.
  - **[개정 2026-08-05 - 사용자 지시] 거래량(F6)은 이 원칙의 예외로 기본 표시**
    한다. 사용자가 "토글 없이 처음부터 보이게"를 반복 요청해 기본값을 전환했다
    (시리즈 기본값도 원주). SMA20/60·기간 평균은 기본 꺼짐 유지.
    상세는 v2 PRD `2026-08-04-v2-features-prd.md` 공통 원칙 1·6절 개정 표기 참고.
- 지표마다 계산식을 수식 안내 섹션에 추가(투명성 차별점 유지).
- z-score 등 통계 지표 도입 시 "투자 조언 아님" 고지를 차트 영역에도 병기.
