## 2. 아키텍처 개요

2단계 구성: **오프라인 데이터 파이프라인(Python) + 정적 웹 UI(순수 HTML/CSS/JS)**.
서버 사이드 로직이 없으며, 파이프라인이 생성한 정적 JSON을 웹이 읽기만 한다.

```
[설정] src/config/tickers.json          (종목·전환비율·환율 매핑·노출 순서)
   |
   v
[수집·계산] src/fetch_data.py  --(yfinance)--> Yahoo Finance
   |   - 종목별 DR 종가·원주 종가·환율의 일별 히스토리(period=max, 원시 종가) 수집
   |   - 규칙 B(PRD 3.3.1)로 일별 프리미엄 계산: 날짜 그리드는 DR/원주 거래일 합집합,
   |     휴장 쪽은 직전 종가 이월(forward-fill) + ff_dr/ff_local/ff_fx 플래그
   |   - 규칙 A 근사 스냅샷: 각 시리즈의 최신 종가 + 각각의 기준 날짜
   |   - 종목별 조회 실패 시: 직전 정상 데이터 유지 + fetch_error 기록 (파이프라인 계속)
   v
[정적 데이터] src/web/data/meta.json         (순서·스냅샷·30일 스파크라인·오류 플래그)
             src/web/data/history/<ID>.json (일별 프리미엄 히스토리)
   |
   v
[프리렌더] src/build_pages.py  (SEO D1~D4, 2026-08-04 추가)
   |   - meta.json + config/site.json + 가이드 원고(docs/marketing/guides/*.md)를
   |     읽어 완전한 HTML을 생성: 메인 1 + 종목 11 + 가이드 N + sitemap.xml + robots.txt
   |   - 초기 HTML에 핵심 콘텐츠가 텍스트로 포함 (JS 없이 크롤러가 읽음):
   |     종목명·프리미엄 %·원천값 4종·수식·고지 + 메인 스파크라인 SVG까지 서버 생성
   |   - 페이지별 title/meta description/OG/canonical (마케팅 문서 2.3절 템플릿)
   |   - JSON-LD: 메인 WebSite+Organization, 종목 BreadcrumbList,
   |     가이드 FAQPage(원고에 Q&A 섹션이 있을 때만 - 남용 방지)
   v
[웹 UI] src/web/ (경로 기반 정적 페이지 + styles.css + app.js, 의존성 0)
   - URL: / (메인), /stocks/skhy/ 등 소문자 DR 티커 경로, /guide/<slug>/
     (정적 호스팅 호환을 위해 각 경로는 index.html 파일로 생성)
   - app.js는 하이드레이션만 담당: 테마 토글(전 페이지) + 종목 상세의
     기간 탭·SVG 차트·툴팁 (body[data-page]/[data-root]로 페이지 판별·경로 계산)
   - 구 해시 URL(#/SKHY)은 head 인라인 스크립트가 알려진 티커일 때만
     /stocks/<ticker>/ 로 location.replace (D1 리다이렉트 요건)
   - 다크모드: CSS 변수 + data-theme 속성 + localStorage (기존과 동일)
```

실행 순서: fetch_data.py -> build_pages.py. 프리렌더는 파이프라인 생성물(JSON)의
소비자이며, 검증 완료된 수집·계산 코드는 변경하지 않았다.

프리미엄 수식 (PRD 3.3절 그대로):

```
Premium(%) = (P_dr * FX / (P_local * r) - 1) * 100
```

## 7. 알려진 제약사항

1. **yfinance는 상업 이용 불가** - 비공개 프로토타입 한정 (사용자 승인 범위).

2. **정적 데이터 - 갱신은 재실행 필요**: `fetch_data.py` + `build_pages.py`를
   재실행해야 화면 수치(프리렌더 HTML)와 차트 데이터(JSON)가 함께 갱신된다.
   자동화 준비물은 마련됨(5절 D5) - GitHub Actions는 저장소 생성 후 활성화,
   그 전에는 Windows 작업 스케줄러 등록 스크립트 사용. GitHub Actions 스케줄
   운영 유의 2건(기획 문서 4절 제안 D): (1) 정시 보장 없음 - 10~30분 지연이

   일별 데이터 커밋이 생기면 사실상 해소되나 연속 실패 시 재발 가능하므로 운영
   체크리스트로 관리.

   확정 종가가 아니다. 기준 날짜는 정확히 표기되며, 장 마감 후 재수집하면 확정된다.
4. **전환비율 변경 이력**: 비율이 변경된 3종목(삼성전자·SK텔레콤·신한지주)은
